## Task

Example Component A owns the declaration: it accepts submissions, decides whether they are
formally and legally acceptable, stores every revision immutably, and announces every state
change as an event. It is the only component in
[Example System A](/systems/example-system-a/) that writes declaration state.

What it deliberately does **not** do: assess risk (that is
[Example Component B](/systems/example-system-a/components/example-component-b/)), calculate
duties, or schedule controls.

## Quality goals

| Priority | Goal | Scenario |
| --- | --- | --- |
| 1 | **No accepted declaration is ever lost** | A declaration acknowledged to the trade portal is durably stored and its event is published, even if the component crashes between the two — this is what forces the [transactional outbox](/systems/example-system-a/components/example-component-a/architecture-decisions/adr-0001-transactional-outbox/). |
| 2 | **Comprehensible rejections** | A rejected declaration names the violated rule, the field and the accepted values. |
| 3 | **Intake availability** | Acceptance continues while every downstream consumer is unavailable. |

## Stakeholders

| Role | Expectation of this component |
| --- | --- |
| Declarant (via trade portal) | Fast acknowledgement, actionable rejection reasons |
| Example Component B | Complete, ordered declaration events with a stable schema |
| Audit Trail Service | Immutable revision history, nothing overwritten |
| Operations | Idempotent replay, no payloads in operational tooling |
