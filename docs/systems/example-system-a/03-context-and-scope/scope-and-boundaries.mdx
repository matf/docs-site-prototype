## Scope in one sentence

Example System A owns the declaration from the moment it is submitted until the consignment is
cleared or handed to inspection planning — everything before (trade software) and after (duty
assessment, physical control) belongs to somebody else.

## What is deliberately outside the boundary

- **Duty and tax assessment.** A separate system consumes `DeclarationCleared` and calculates the
  amounts. Example System A never computes money. Keeping assessment out means a change to a duty
  rate never touches this system.
- **Physical control execution.** Inspection Planning schedules and records the control; the
  outcome comes back as a business event, not as a call into this system. The border process must
  keep working when this system does not.
- **Traveller information.** Owned by [Example System B](/systems/example-system-b/). The two
  systems share no data and no schedule.

## Why the boundary sits here

The boundary follows **who is accountable for the decision**, not who holds the data. Example
System A decides whether a consignment may proceed; every neighbour either supplies an input to
that decision or acts on its outcome. Anything that would make this system responsible for a
second decision — how much duty is owed, which officer performs a control — was pushed out.

That rule is what keeps the interface list in the generated diagram short. When a new integration
is proposed, the first question is which decision it belongs to.
