## Definition of done

A story is done when all of the following hold. Nothing here is negotiable per story — a story that
cannot meet a gate becomes a smaller story.

| # | Gate | Evidence |
| --- | --- | --- |
| G-1 | Every acceptance criterion has an automated test | Test names reference the criterion number |
| G-2 | Contract tests pass for every message the story touches | Consumer contracts run against the producer |
| G-3 | Architecture tests pass | Layering, logging annotations, determinism |
| G-4 | No business payload appears in logs or operational tooling | Automated check |
| G-5 | The affected documentation is updated or regenerated | Build is green with no broken links |

## Test levels

| Level | Owns | Runs |
| --- | --- | --- |
| Unit | Domain rules | Every build |
| Contract | Message schemas | Every build |
| Integration | Component with real broker and database | Every build |
| Load | The peak profile | Before each release |
| Chaos | Neighbour outages | Before each release |
| Audit rehearsal | Reproducibility of old decisions | Twice a year |

The architectural counterpart is
[10. Quality Requirements](/systems/example-system-a/system-architecture/quality-requirements/),
which expresses the same expectations as measurable scenarios. This page is about *when a story is
allowed to be called finished*; that one is about *what the system must demonstrably do*.
