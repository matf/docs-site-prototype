> **As a** declarant
> **I want** to submit a goods declaration and be told immediately whether it was accepted
> **so that** I can fix a mistake before the consignment reaches the border.

## Acceptance criteria

1. **Given** a structurally valid declaration that satisfies the customs rules, **when** it is
   submitted, **then** it is stored as revision 1 and acknowledged as accepted.
2. **Given** a declaration that violates a customs rule, **when** it is submitted, **then** it is
   rejected with the rule identifier, the field path and the accepted values, and nothing is stored.
3. **Given** the same submission delivered twice, **when** both are processed, **then** only one
   declaration exists.
4. **Given** the tariff service is unavailable, **when** a declaration is submitted, **then**
   validation continues from the cache and the decision is unaffected.

## Implementation notes

Criterion 3 is the reason the component carries a processed-message table; criterion 4 is the
reason the rule client caches for 24 hours. Both are described in
[Example Component A — 5. Building Block View](/systems/example-system-a/components/example-component-a/system-architecture/building-block-view/).
