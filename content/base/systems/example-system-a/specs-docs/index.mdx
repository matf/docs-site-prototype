The specification chain of Example System A, following the **BMAD** method: a brief agrees the
problem, the product requirements make it precise, the architecture says how it is realised, and
epics and stories shard it into units a team can implement.

:::note[Two structures, one system]

This system carries two documentation structures side by side. **Specification Docs** says *what*
is to be built and *why*; <StructureLink system="example-system-a" structure="system-architecture" />
says *how it is structured*. They are deliberately not merged — they have different authors,
different review cycles and different lifetimes, and a reader almost always wants one or the other
rather than both interleaved.

Where they touch, they link: [3. Architecture](/systems/example-system-a/specs-docs/architecture/)
is a short page that defers to the arc42 description instead of repeating it.

:::
