The system glossary in
[Example System A — 12. Glossary](/systems/example-system-a/system-architecture/glossary/) applies. Only terms that
are specific to this component are listed here.

The names in the code are extracted automatically into
[Domain Model Terms](/systems/example-system-a/components/example-component-a/system-architecture/glossary/domain-model-terms/). This page
covers the words that are easy to get wrong.

## Terms used carefully

| Term | Note |
| --- | --- |
| **Accepted** | Means "formally valid and stored". It says nothing about risk and nothing about clearance. Declarants read it as "done", which is why the portal wording was reviewed with the specialist unit. |
| **Superseded** | A decision that arrived for a revision that is no longer current. Superseded decisions are discarded, not queued — see [6. Runtime View](/systems/example-system-a/components/example-component-a/system-architecture/runtime-view/). |
| **Rejected** | A business outcome, never a technical failure. A message that cannot be processed is dead-lettered, not rejected. |
