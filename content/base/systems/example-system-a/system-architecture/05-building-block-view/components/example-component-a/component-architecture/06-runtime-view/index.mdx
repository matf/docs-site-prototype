## Scenario — submission to clearance

The reaction graph shows what reacts to what; this sequence shows the same flow with the internal
building blocks, which is what you need when something goes wrong in the middle.

```mermaid
sequenceDiagram
  autonumber
  participant BR as Broker
  participant MIN as Messaging Adapter (in)
  participant APP as Application Service
  participant DOM as Domain
  participant PERS as Persistence Adapter
  participant MOUT as Outbox Relay
  participant B as Example Component B

  BR->>MIN: SubmitDeclaration
  MIN->>MIN: map national specification → internal model
  MIN->>APP: registerDeclaration(command)
  APP->>PERS: seen(messageId)?
  PERS-->>APP: no
  APP->>DOM: Declaration.register(...)
  DOM->>DOM: structural + customs rule validation
  DOM-->>APP: revision 1, state ACCEPTED
  APP->>PERS: save(revision) + outbox(DeclarationAccepted) + processed(messageId)
  Note over APP,PERS: one transaction — this is the whole point of the outbox
  PERS-->>APP: committed
  APP-->>MIN: acknowledged
  MOUT->>PERS: poll outbox
  MOUT->>BR: publish DeclarationAccepted
  BR->>B: DeclarationAccepted
  B-->>BR: RiskAssessmentCompleted (band = low)
  BR->>MIN: RiskAssessmentCompleted
  MIN->>APP: applyRiskDecision(event)
  APP->>DOM: clear(revision 1)
  APP->>PERS: save(state CLEARED) + outbox(DeclarationCleared)
  MOUT->>BR: publish DeclarationCleared
```
