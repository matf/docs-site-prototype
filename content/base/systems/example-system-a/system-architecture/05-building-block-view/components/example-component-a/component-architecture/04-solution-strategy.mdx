## Why the outbox rather than "publish then commit"

Publishing the event before committing the transaction risks an event for a declaration that does
not exist. Committing first and publishing after risks an accepted declaration that nobody hears
about — and that is the worse failure, because the declarant already has an acknowledgement.

The outbox makes the two writes atomic and moves the publishing problem to a relay that can retry
forever. The price is at-least-once delivery, which every consumer already has to handle under
[ADR-0001 of the system](/systems/example-system-a/system-architecture/architecture-decisions/adr-0001-event-driven-integration/).

## Why append-only revisions

The alternative — updating the declaration in place and keeping a change log — was rejected
because the change log then has to be complete and correct to satisfy the ten-year
reconstruction requirement, and a change log is exactly the thing that quietly stops being
complete. With append-only revisions, the current state is a projection of the history, so the
history cannot be wrong without the present being visibly wrong.
