## Task

Example Component B decides how much attention a consignment deserves. For every accepted
declaration revision it opens a risk case, evaluates the current rule set, scores the case with
the current model, and publishes a decision: `low`, `elevated` or `high`. High cases become
inspection orders.

It does not hold declarations, does not release consignments and does not schedule controls — it
only decides and announces.

## Quality goals

| Priority | Goal | Scenario |
| --- | --- | --- |
| 1 | **Reproducibility** | A decision from three years ago can be recomputed and yields the same band, because the rule set and model versions are recorded with the decision. |
| 2 | **Changeability without deployment** | A risk analyst publishes a new rule set and it becomes effective within five minutes, with no software release. |
| 3 | **Throughput** | The event backlog after an outage drains faster than it accumulates, so a delay never becomes permanent. |

Reproducibility outranks latency here, which is the opposite of
[Example Component A](/systems/example-system-a/system-architecture/building-block-view/example-component-a/). A risk decision
that arrives two seconds late is fine; one that cannot be explained is not.

## Stakeholders

| Role | Expectation |
| --- | --- |
| Risk analyst | Publish rules and models safely; see their effect immediately; roll back in one step |
| Customs officer | A decision that carries its reasons — which rules fired, which band, why |
| Example Component A | A decision for every revision it announces, exactly once per revision |
| Legal / audit | Every past decision reproducible for ten years |
