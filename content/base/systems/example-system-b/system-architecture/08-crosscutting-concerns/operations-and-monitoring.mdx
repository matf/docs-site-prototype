## Service level objectives

| Indicator | Objective |
| --- | --- |
| Public site availability | 99.9 % (cached path) |
| Freshness | Waiting times marked stale within 10 minutes of the last measurement |
| Notification delivery | 95 % within 2 minutes |
| Cache hit ratio during a spike | Above 98 % |

## Alerts

| Alert | Trigger | First action |
| --- | --- | --- |
| `sensor-feed-stale` | No measurement for 10 minutes | Confirm with the sensor platform team; the site self-marks as stale meanwhile |
| `notification-backlog` | Undelivered notifications older than 5 minutes | Check the provider status; batching is rate-aware and will catch up |
| `cache-miss-spike` | Hit ratio below 90 % for 5 minutes | Verify that invalidation is not looping |

## Correcting a wrong announcement

A delivered notification cannot be recalled, and there is no technical mitigation for that. The procedure is a correction
broadcast that references the original message identifier, sent on the same channels, in all four
languages.
