# Systems

Every BAZG system documented in this prototype. Opening a system shows the documentation
structures it carries — an arc42 **System Architecture**, and where it exists a BMAD
**Specification Docs** set — with its components inside the architecture's *5. Building Block
View*, next to the contracts that flow between them.

## What a system entry contains

| Level | Contains | Example route |
| --- | --- | --- |
| System | Its documentation structures | `/systems/example-system-a/` |
| Documentation structure | The sections of one methodology | `/systems/example-system-a/system-architecture/` |
| Section | A chapter of that methodology | `/systems/example-system-a/system-architecture/building-block-view/` |
| Child page | Filed under the section it belongs to | `/systems/example-system-a/system-architecture/crosscutting-concerns/security-and-data-protection/` |
| Component | A building block, documented inside *5. Building Block View* | `/systems/example-system-a/system-architecture/building-block-view/components/example-component-a/` |
| Component section | The component's own Component Architecture | `…/example-component-a/component-architecture/runtime-view/` |

## Adding a system

A system is a folder under `content/base/systems/`. Adding the folder with its `_category_.json` and an
`index.mdx` is enough — the sidebar is generated from the filesystem, so no navigation
configuration has to be touched. The exact layout is described in
[Documentation conventions](/conventions/).
